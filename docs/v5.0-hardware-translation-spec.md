# V5.0 — Hardware Translation Spec

## Status

Draft for acceptance.

## Purpose

V5.0 translates the accepted Merrin Grief Synth browser reference into a hardware architecture.

The final destination is:

```text
Merrin Grief Synth — Constrained Grief
as a real circuit-board instrument.
```

The browser version remains the proof-of-voice, control-language, and behaviour reference.

V5.0 does not begin schematic capture or PCB work.

## Two truths that must remain together

### Existing voice canon

The established Merrin Voice 01 signal language is:

```text
SCALE
  ↓
TONE
  ↓
ENVELOPE
  ↓
ROOM
  ↓
MEMORY
```

The older Eurorack hardware canon expresses that as:

```text
MV-02 Melancholy Quantizer
  ↓
MV-01 Somber Oscillator
  ↓
MV-03 Lingering Voice
  ↓
MF-01 Desolate Space
  ↓
MF-02 Fading Echoes
```

This remains valid source material.

### Newest hardware-heart decision

The circuit-board instrument is not to begin with the oscillator.

Its defining heart is:

```text
MEMORY
GHOST
RETURN
```

The support states/blocks are:

```text
ABSENCE
PRESSURE
BREAK
```

Oscillators, quantisation, and the internal voice source are secondary support systems.

The first practical prototype must prove the grief engine before an oscillator board is designed.

## What grief means in the hardware

The instrument should express grief through:

- persistence
- absence
- distortion under pressure
- unreliable return
- coexistence between the present signal and what remains of the past

The instrument is not defined by simply playing a minor scale through reverb.

The source voice matters, but the distinctive instrument behaviour comes from how sound is retained, thinned, damaged, and returned.

## Locked architecture decision

The hardware direction is hybrid.

```text
Analogue present path
+
shared digital Memory / Ghost / Return core
+
analogue nonlinear Return and safety path
```

### Analogue present path

The present signal should have a direct, stable hardware path through input handling, gain control, and output mixing.

The instrument must remain usable if the memory engine is at minimum.

### Shared digital core

Memory, Ghost, and Return share one digital audio-memory core.

This is not three unrelated effects placed in series.

They are three behaviours derived from the same retained sound.

### Analogue Return path

Return includes a nonlinear analogue stage and a controlled feedback path.

It reintroduces altered past sound into future memory and can influence the Absence block.

The feedback path must be limited and live-safe.

## Functional blocks

### 1. Present

Present is the current incoming signal.

For the first prototype, Present comes from an external audio input.

This avoids building an oscillator before the defining grief engine has been proven.

Later, Present may come from the internal constrained voice source.

### 2. Absence

Absence is spectral removal.

It is not merely a low-pass filter labelled with an emotional name.

It should remove or hollow parts of the sound so the retained signal feels incomplete.

Locked meaning:

```text
spectral removal / missing content
```

Return may modulate the Absence centre or depth so earlier sound changes what the current sound loses.

### 3. Pressure

Pressure is controlled gain stress.

Locked meaning:

```text
gain
saturation
compression
```

Pressure should make the signal feel constrained and burdened without turning the instrument into an ordinary distortion effect.

### 4. Break

Break is controlled instability and cumulative damage.

Locked meaning:

```text
controlled instability
clipping
folding
feedback saturation
compression
soft clipping
bandwidth loss
cumulative degradation
```

Break belongs primarily in the retained/returning sound path rather than acting as a generic input distortion.

Its exact position remains a circuit-design question, but its emotional job is locked.

### 5. Memory

Memory retains and degrades earlier sound.

Locked behaviour:

- circular audio buffer
- repeating fragments
- smearing
- bandwidth reduction
- slight modulation
- soft limiting
- degradation over repeated circulation

Locked control language:

| Control | Meaning |
|---|---|
| Time | How far back the retained sound reaches. |
| Fade | How quickly retained sound loses authority. |
| Blur | How much detail is lost while it remains. |

Memory must not sound like a clean utility delay.

### 6. Ghost

Ghost is derived from Memory.

It is not a second independent oscillator and not an unrelated noise layer.

Locked behaviour:

- thinner than Memory
- detached from the present signal
- delayed or displaced
- subtly drifted
- partly obscured

Locked control language:

| Control | Meaning |
|---|---|
| Distance | How separated the Ghost feels from the present sound. |
| Drift | How unreliable its timing or pitch relationship becomes. |
| Presence | How audible the Ghost becomes without taking over. |

### 7. Return

Return is altered past sound re-entering the system.

It does two jobs:

1. feeds changed sound back into Memory
2. influences future behaviour, including Absence

Return is not ordinary delay feedback.

It should make the instrument remember differently because of what has already happened.

Return must include:

- a controlled amount path
- nonlinear alteration
- feedback limiting
- a safe reset/mute state
- an influence path to Absence

## Functional signal flow

```text
EXTERNAL AUDIO / LATER INTERNAL VOICE
                │
                ▼
       [Input protection / level]
                │
                ▼
          [Analogue Present]
                │
        ┌───────┴────────┐
        │                │
        ▼                ▼
   [Pressure]        [Memory input]
        │                │
        ▼                ▼
   [Absence]     [Shared digital Memory core]
        │                │
        │          ┌─────┴─────┐
        │          ▼           ▼
        │       [Memory]     [Ghost]
        │          │           │
        │          └─────┬─────┘
        │                ▼
        │          [Break / Return shaping]
        │                │
        │          ┌─────┴──────────────┐
        │          │                    │
        │          ▼                    ▼
        │   back into Memory     modulate Absence
        │
        └──────────────┬─────────────────┘
                       ▼
             [Present / Memory / Ghost mix]
                       │
                       ▼
              [Output safety / level]
                       │
                       ▼

```

This diagram defines function, not circuitry.

## Relationship to the old five-module system

The old five-module system is not deleted.

Its roles translate as follows:

| Existing canon block | Hardware-translation role |
|---|---|
| Scale / MV-02 | Later constrained-pitch support system. Not required for Memory Core Prototype A. |
| Tone / MV-01 | Later internal Present source. Oscillator design is deferred. |
| Envelope / MV-03 | Later internal voice dynamics and possible modulation source. External audio stands in during Prototype A. |
| Room / MF-01 | Spatial evidence to be reconciled with Memory/Ghost after the core is proven. No separate reverb block in Prototype A. |
| Memory / MF-02 | Expanded into the Memory/Ghost/Return heart rather than copied as a conventional delay. |

The physical packaging is not locked by V5.0.

V5.0 does not decide whether the final instrument is:

- one integrated desktop board
- one Eurorack voice plus separate effects
- several linked boards

That decision must follow prototype evidence.

## Input, control, and I/O strategy

### Prototype A

Prototype A should use:

- mono external audio input
- mono audio output
- manual panel controls
- internal test points or headers for Present, Memory, Ghost, and Return
- a programming/debug connection appropriate to the later circuit design

Prototype A should not require:

- MIDI
- a keyboard
- an internal oscillator
- a quantizer
- presets
- menus
- a display
- a sequencer

### Later control integration

MIDI, CV, control scanning, and the internal constrained voice are later layers.

V5.0 requires the architecture to leave clean interfaces for them, but Prototype A should not be delayed by them.

## SLS-1 state-light requirements

State lights must follow `MERRIN-STD-SLS-1`.

Prototype A needs only meaningful state indication.

Required state meanings:

| State | Meaning |
|---|---|
| IDLE | Powered and safe; memory engine not retaining significant sound. |
| ACTIVE | Memory/Ghost/Return engine is active. |
| WARNING | Return or Pressure is approaching the safe operating limit. |
| ERROR | Core, buffer, or control system is not in a safe known state. |

Rules:

- no decorative flashing on state LEDs
- rhythm must carry meaning; colour is secondary
- warning/error must override activity indication
- boot or fault must never falsely indicate ACTIVE or safe Return
- no pattern may exceed the SLS-1 sensory-safety limit

Audio meters, if added later, are separate from state lights.

## HIL-1 layout requirements

The panel and bench interface must follow `MERRIN-STD-HIL-1`.

Required rules:

- controls above, jacks below by default
- Memory, Ghost, and Return grouped as the central performance area
- safety/mute/reset easy to find but difficult to trigger accidentally
- state LEDs placed near the function they describe
- debug/programming connections kept away from the playing area
- cables must not cross the main hand controls in normal use
- dangerous feedback controls must have clear range and state indication

Prototype A is a test instrument, but it must still be playable enough to judge the behaviour honestly.

## Safety and recovery requirements

The hardware must fail toward silence or stable bypass, not runaway output.

Required behaviours:

1. Return feedback is hard-limited below destructive runaway.
2. Pressure and Break cannot create unsafe output jumps.
3. Boot/reset begins muted or at a known safe gain.
4. Core fault produces ERROR state and safe output behaviour.
5. Reset/clear-memory returns the instrument to a known state.
6. External audio loss does not leave uncontrolled feedback circulating indefinitely.
7. Output level remains independently controllable.
8. The analogue Present path remains recoverable even if the memory core is reset.

## First prototype boundary

The first practical hardware build is:

```text
Memory Core Prototype A
```

Its job is to prove:

- an external sound can remain present
- Memory retains and degrades it
- Ghost is derived from Memory and feels thinner/detached
- Return changes what Memory does next
- Return can influence Absence
- Pressure and Break create controlled damage rather than generic distortion
- the system remains safe under feedback and reset

Prototype A is not:

- the final synth
- the oscillator board
- the quantizer board
- the five-module Eurorack system
- the final panel
- a production PCB
- a product-ready enclosure

## Prototype A acceptance tests

### Identity

- A listener can hear Present, Memory, Ghost, and Return as different roles.
- Memory does not sound like a clean normal delay.
- Ghost cannot be mistaken for a second normal voice.
- Return changes future behaviour rather than merely adding repeats.

### Behaviour

- Time, Fade, and Blur remain musically distinct.
- Distance, Drift, and Presence remain musically distinct.
- Absence removes content rather than only darkening it.
- Pressure constrains and compresses before it becomes ordinary distortion.
- Break produces controlled cumulative damage.

### Safety

- Return cannot reach uncontrolled runaway.
- Reset/clear returns to a known safe state.
- Power-on does not create a full-level transient.
- Output remains controllable at every setting.
- Fault state is visibly different from ACTIVE.

### Scope discipline

- No oscillator is required to pass the test.
- No MIDI or CV system is required to pass the test.
- No display, menu, preset, or sequencer is required.
- The prototype produces an emotionally recognisable result within 30 seconds of use.
