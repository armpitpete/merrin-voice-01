# V5.1 — Memory Core Prototype A Circuit-Block Design

## Status

Draft for acceptance.

## Goal

Define the functional circuit-block structure for **Memory Core Prototype A** before schematic capture or component selection.

Prototype A must prove:

```text
MEMORY
GHOST
RETURN
```

with:

```text
ABSENCE
PRESSURE
BREAK
```

The prototype uses external mono audio as **Present**.

## Core refinement

Memory captures **shaped Present**, after Pressure and Absence.

```text
Raw input
  ↓
Pressure
  ↓
Absence
  ↓
Shaped Present
  ├── direct analogue Present path
  └── Memory-input summing node
```

Return re-enters only through the Memory-input summing node after Break, analogue Return shaping, and hard limiting.

This means the instrument remembers what the present sound has already become.

## Signal-domain targets

These are Prototype A targets, not final-format claims.

| Domain | Target |
|---|---|
| Expected external input | Approximately 0.2–10 Vpp after user trim. |
| Input survival | No damage from a continuous input within ±12 V at the jack. |
| Internal analogue nominal | 2 Vpp. |
| Internal analogue headroom | At least 6 Vpp before unintended clipping. |
| Converter ingress nominal | Approximately −12 dBFS. |
| Converter ingress peak | Below −3 dBFS before intended limiting. |
| Digital controls | Normalised 0.0–1.0 values. |
| Final output nominal | Approximately 2 Vpp. |
| Final output maximum | No more than 10 Vpp during normal operation. |
| Return small-signal target | Approximately 0.85 maximum before nonlinear limiting. |
| Return absolute condition | The complete loop remains bounded at every valid setting. |

Power rails, analogue reference, converter supplies, and control-voltage rails remain deferred.

## Block definitions

### IN-01 — Thonkiconn audio input

Purpose:

- receive mono external audio
- provide a mechanically robust PCB/panel connection
- define a safe no-cable state

Requirements:

- Thonkiconn connector family
- exact variant deferred
- switched-contact behaviour documented before schematic acceptance
- no floating input with no cable
- mechanical load must not rely only on fragile solder joints

### IN-02 — Input protection and RF rejection

Purpose:

- tolerate patching mistakes
- limit current before sensitive circuitry
- reduce cable-borne RF/interference

Requirements:

- meet the input-survival target
- avoid audible loading in the expected range
- fail toward attenuation or silence

### IN-03 — Input trim and buffer

Purpose:

- accept lower-level and modular-level sources
- create the internal nominal level
- present stable loading to the source

Requirements:

- manual trim
- repeatable unity/reference position
- enough attenuation for the expected maximum input
- enough usable gain/buffering for lower-level sources
- no emotional shaping here

### PRS-01 — Pressure

Purpose:

Apply controlled gain stress before Memory capture.

Pressure means:

- gain
- saturation
- compression
- constrained dynamic movement

Requirements:

- continuously controllable amount
- near-clean minimum
- progressive compression/saturation
- bounded output into Absence
- no unsafe level jump
- clearly different behaviour from Break

### ABS-01 — Absence

Purpose:

Remove or hollow spectral content before direct and remembered paths split.

Requirements:

- continuously controllable depth
- removes content rather than only reducing level
- bounded Return-derived influence
- cannot enter unstable gain behaviour
- neutral or safe state during reset/fault

Exact topology is deferred.

### PRES-01 — Direct Present path

Purpose:

Keep a stable analogue route around the digital core.

Requirements:

- no ADC/DAC traversal
- remains available during digital boot/reset/fault
- defined relationship to the wet path
- no digital fault noise
- muteable only by the final safety/output system

### SUM-01 — Memory-input summing node

Purpose:

Combine:

1. shaped Present
2. safely limited Return

before ADC conversion.

Requirements:

- shaped Present remains the normal reference input
- Return rises smoothly
- no raw Return reaches this node
- enough headroom for Present plus Return
- controlled overload behaviour

### ADC-01 — Digital ingress

Purpose:

Convert the summed shaped-Present/Return signal into the shared digital core.

Requirements:

- one functional mono ingress
- anti-alias conditioning
- nominal level near −12 dBFS
- peak target below −3 dBFS before intended limiting
- converter clipping is not used as Break

Exact converter, rate, depth, and filter topology are deferred.

### CORE-01 — Shared digital core

One retained history creates Memory, Ghost, and Return send.

It is not three unrelated effects.

#### Memory

Required controls and behaviour:

- Time
- Fade
- Blur
- circular retained-audio storage
- repeated-circulation degradation
- smearing/bandwidth loss
- bounded digital output

#### Ghost

Ghost is derived from Memory.

Required controls and behaviour:

- Distance
- Drift
- Presence
- thinner than Memory
- displaced or detached
- subordinate at default settings

#### Return send

Required behaviour:

- derived from retained sound
- bounded digitally
- Return amount applied before or at DAC-R
- immediately forced to zero by reset/fault
- cannot bypass the analogue Return chain

### DAC-M — Memory output

Requirements:

- dedicated functional output
- reconstruction filtering
- known nominal level into wet mix
- muteable on boot/reset/fault

### DAC-G — Ghost output

Requirements:

- dedicated functional output
- reconstruction filtering
- default level below Memory
- muteable on boot/reset/fault

### DAC-R — Return-send output

Requirements:

- dedicated functional output or equivalent isolated channel
- reconstruction filtering
- zero during reset/fault
- no direct connection to SUM-01

V5.1 locks three functional outputs, not converter part count.

### BRK-01 — Break

Purpose:

Create cumulative damage in the returning path.

Later schematic behaviour may include:

- soft clipping
- folding
- compression
- bandwidth loss
- feedback saturation
- controlled instability

Requirements:

- continuously controllable amount
- intelligible low setting
- bounded high setting
- no bypass around Return safety
- clearly different from Pressure

### RET-01 — Analogue Return nonlinear stage

Purpose:

Physically alter returned sound before it changes future Memory.

Requirements:

- receives only DAC-R
- adds analogue nonlinearity distinct from digital degradation
- stable with silence, sustained tones, and DC-like content
- no full-level transient when Return rises
- feeds RET-02 only

### RET-02 — Hard Return limiter

Purpose:

Make uncontrolled feedback structurally unavailable during normal use.

Requirements:

- fixed upper bound independent of Return knob
- limits both polarities
- remains effective during digital faults
- feeds both recirculation and Absence influence
- no hidden bypass

Target:

```text
Normal maximum small-signal loop gain ≈ 0.85
Complete-loop behaviour = bounded
```

### RET-03 — Absence influence

Purpose:

Derive a slow, bounded control influence from limited Return.

Requirements:

- responds to Return, not raw input
- smoothing prevents uncontrolled chatter
- cannot exceed ABS-01 safe range
- neutral during reset/fault
- dedicated test point

### RET-04 — Limited Return feed

Purpose:

Feed altered past sound back to SUM-01.

Requirements:

- receives RET-02 only
- fixed attenuation/bounding independent of user Return amount
- forced to zero by SAFE-01
- dedicated test point

### MIX-01 — Wet mix

Combines Memory and Ghost.

Requirements:

- separate functional level control internally
- Ghost subordinate by default
- wet headroom preserved
- wet path muteable independently of Present

### MIX-02 — Final mix

Combines direct Present and wet mix.

Requirements:

- Present remains available at wet minimum
- useful wet range without unintended clipping
- no accidental polarity cancellation
- Return is heard mainly through changed future Memory and Absence, not as an unrelated fourth effect channel

### OUT-01 — Output level

Requirements:

- spans silence to defined maximum
- follows final mix
- repeatable reference position
- cannot bypass OUT-02

### OUT-02 — Safe mute and output protection

Requirements:

- hardware-capable wet mute
- known safe power-on state
- controlled mute release
- maximum normal output no greater than 10 Vpp
- protected, stable drive to output Thonkiconn

### CTRL-01 — Manual controls

Expressive controls:

- Pressure
- Absence
- Break
- Memory Time / Fade / Blur
- Ghost Distance / Drift / Presence
- Return amount

Operating controls:

- input trim
- Present/wet balance
- output level
- bypass or safe mute
- reset/clear Memory

Rules:

- no menu or display
- digital values normalised 0.0–1.0
- analogue controls remain analogue where useful
- disconnected/noisy controls fail to bounded values

### SAFE-01 — Boot, reset, mute, and fault control

Required states:

```text
POWER-OFF
BOOT-MUTED
IDLE-SAFE
ACTIVE
RESET-MUTED
WARNING-LIMIT
ERROR-MUTED
```

Required sequence:

1. Power-on starts with wet and Return muted.
2. Direct Present becomes available only after analogue stability.
3. Wet unmute waits for valid CORE-01 state.
4. Reset immediately forces Return send/feed to zero.
5. Memory clears while wet remains muted.
6. Unmute uses a controlled ramp.
7. Core/watchdog fault forces ERROR-MUTED.
8. Direct Present remains recoverable unless final safety mute is engaged.

Target:

- emergency wet/Return suppression begins within 20 ms
- normal unmute only follows stable-state confirmation

### LED-01 — SLS-1 indication

| State | Meaning |
|---|---|
| IDLE | Powered, stable, little/no retained sound. |
| ACTIVE | Memory/Ghost/Return active. |
| WARNING | Pressure/Return/limiter near safe boundary. |
| ERROR | Invalid core/safety state; wet/Return muted. |

SLS-1 precedence, rhythm, colour-independence, and sensory limits apply.

## Conversion boundaries

### Analogue to digital

ADC receives only:

```text
shaped Present + limited Return
```

It must not receive:

- raw untrimmed input
- raw DAC-R output
- unbounded Return
- final output-mixer signal

### Digital to analogue

Three functional outputs are required:

```text
Memory
Ghost
Return send
```

A multichannel converter or equivalent architecture may implement them later.

This is partitioning guidance, not PCB placement.

### Zone A — Panel/mechanical edge

- Thonkiconns
- controls/switches
- state LEDs
- mounting

### Zone B — Quiet analogue input

- IN-02 / IN-03
- PRS-01 / ABS-01
- PRES-01 / SUM-01

### Zone C — Conversion boundary

- ADC conditioning
- DAC reconstruction
- controlled analogue/digital reference relationship

### Zone D — Digital core

- CORE-01
- digital control acquisition
- programming/debug
- state monitoring

### Zone E — Return/high-energy analogue

- BRK-01
- RET-01 / RET-02 / RET-03 / RET-04

This zone must not contaminate quiet input/reference paths.

### Zone F — Mix/output/safety

- MIX-01 / MIX-02
- OUT-01 / OUT-02

### Zone G — Power/reference

- power entry/protection

## Ground/reference rules

- analogue and digital return currents are intentionally controlled
- digital clock/current loops avoid quiet input and Absence nodes
- converter/analogue reference relationship is explicit in the schematic
- Thonkiconn sleeves follow one documented grounding strategy
- panel hardware creates no undocumented second ground path
- Return/high-gain currents do not share sensitive input paths

V5.1 does not prescribe a final ground-plane layout.

## Bench acceptance procedure

### 1. Documentation

Confirm:

- every block exists
- every interface has one direction
- required test points are present
- no Return path bypasses RET-02
- direct Present bypasses the digital core

### 2. Power-off safety

Verify:

- no hard short between supply domains
- output is not tied to a supply rail
- Return cannot bypass limiter
- Thonkiconn switched contacts match intended no-cable state

### 3. Current-limited power-up

- begin with wet/Return muted
- verify no unsafe transient
- verify truthful IDLE or ERROR state

### 4. Direct Present

With digital core held reset:

- inject known sine
- verify trim range
- verify near-clean Pressure minimum
- verify Absence minimum
- verify Present output path
- verify output-level range

Acceptance:

- unity-reference path within ±1 dB
- no digital noise on direct Present

### 5. Converter loopback

- route shaped Present through ADC/core/DAC-M
- verify −12 dBFS nominal target
- verify peak headroom
- verify stable reconstruction
- verify boot/reset mute

### 6. Memory

Verify Time, Fade, Blur, and cumulative degradation remain distinct.

Memory must not sound like a clean utility delay.

### 7. Ghost

Verify Distance, Drift, and Presence remain distinct.

Ghost must remain derived, thin, detached, and subordinate by default.

### 8. Return

Begin at zero and increase slowly while observing Return test points.

Verify:

- Break alters returning sound
- analogue Return nonlinearity is bounded
- RET-02 acts before runaway
- Return changes future Memory
- Return influences Absence
- no valid control setting escalates uncontrollably

Endurance target:

- 30 minutes at worst valid Return/Break/Pressure settings without runaway, latch-up, or unsafe output

### 9. Reset/fault

Verify:

- wet/Return suppression begins within 20 ms
- Return feed becomes zero
- Memory clears
- controlled unmute waits for stable state
- forced core fault produces ERROR-MUTED
- direct Present remains recoverable

### 10. Input/output boundaries

Verify:

- expected 0.2–10 Vpp inputs trim into nominal range
- survival input causes no damage
- normal output never exceeds 10 Vpp
- output remains controllable at all expressive settings

### 11. Emotional identity

Within 30 seconds a user should hear:

- Present
- Memory
- Ghost
- Return changing what happens next

It must not present as an ordinary delay with renamed controls.
