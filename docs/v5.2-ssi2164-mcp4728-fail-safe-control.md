# V5.2 — SSI2164 / MCP4728 Fail-Safe Control

## Status

Corrected buffered-control authority for exact-part review.

## Purpose

Define the SSI2164 gain law, normal MCP4728 scaling, hardware-default attenuation path, reset/fault timing, and the exact boundary between fast suppression and slower watchdog detection.

This document does not authorise PCB placement, routing, fabrication or purchasing.

# SSI2164 gain law

Prototype A uses the SSI2164 in Class AB mode.

Locked operating relationship:

```text
gain_dB ≈ −VC / 0.033 V
```

Representative points:

| Control voltage | Approximate gain |
|---:|---:|
| −0.66 V | +20 dB |
| 0.00 V | 0 dB / unity |
| +0.33 V | −10 dB |
| +0.66 V | −20 dB |
| +1.65 V | −50 dB |
| +3.30 V | approximately −100 dB |

## Safety consequence

Negative control voltage creates gain.

Therefore the Prototype A SSI2164 control network must obey:

```text
allowed normal control range = 0 V to +3.3 V
```

No user control, DAC output or fault path may drive an SSI2164 control input below 0 V during normal operation.

Each SSI control input uses a local high-impedance OPA4196 unity buffer, a 20 ohm post-buffer isolation resistor, and post-buffer clamps to prevent negative or overrange control voltage.

# Channel allocation

| SSI2164 channel | Function |
|---:|---|
| 1 | Memory wet level |
| 2 | Ghost wet level |
| 3 | Return feed level |
| 4 | wet-master / hardware wet attenuation |

The Return channel cannot bypass the separate analogue Return limiter.

# MCP4728 normal control

The MCP4728 uses:

```text
VREF = VDD
GAIN = 1
normal mode
0x000 → approximately 0 V → SSI unity
0xFFF → approximately 3.3 V → SSI maximum attenuation
```

## User-control mapping

The user-facing level meaning is inverse to the DAC code:

```text
user amount = 0.0 → DAC code 0xFFF → maximum attenuation
user amount = 1.0 → DAC code 0x000 → unity maximum
```

No Prototype A wet/Return channel is permitted to request gain above unity.

A linear user control does not require a linear DAC-code mapping. Firmware may shape the response for useful knob travel, but it must preserve the 0–3.3 V electrical boundary.

## Safe EEPROM state

All four MCP4728 EEPROM channels must be programmed to:

```text
external VDD reference
GAIN = 1
normal power mode
DAC code = 0xFFF
```

This makes the stored state request maximum SSI attenuation.

However, the MCP4728 EEPROM state is not the primary safety mechanism. The MCP4728 datasheet states that EEPROM values load into the DAC registers during power-on reset and become available at the outputs. A corrupt, unprogrammed or unintended EEPROM state could therefore request the wrong gain.

# Independent hardware selector

## Selected function

Add one TMUX1574 four-channel 2:1 analogue switch between the MCP4728 and SSI2164 control inputs.

Package target:

```text
TSSOP-16
```

The TMUX1574 provides:

- four matched 2:1 channels;
- fail-safe logic inputs;
- powered-off protection;
- a weak internal pull-down on `SEL`;
- a common selection input for all four SSI channels.

## Locked connection

For each channel:

```text
SxA = +3.3 V safe-attenuation reference
SxB = MCP4728 channel output
Dx  = local filtered OPA4196 buffer input
```

Control:

```text
EN  = permanently enabled in the datasheet-defined low state
SEL = SAFE_CONTROL_RELEASE
```

Truth used by Prototype A:

```text
SEL low  → SxA selected → +3.3 V → maximum attenuation
SEL high → SxB selected → MCP4728 normal control
```

Because the selector defaults low, loss of MCU drive selects attenuation rather than normal control.

## SAFE_CONTROL_RELEASE network

Locked logic intent:

- `SEL` has an external 100 kΩ pull-down to 0 V.
- MCU `HARDWARE_MUTE_RELEASE` reaches `SEL` through a 10 kΩ resistor.
- supervisor/watchdog/fault logic may pull `SEL` low through an open-drain device.
- MCU high alone cannot release the clamp while a hardware fault asserts low.
- reset, unpowered MCU, floating MCU pin or broken firmware leaves `SEL` low.

Exact transistor/open-drain implementation remains a native schematic task, but the logic must be wired-AND in the safe direction.

## 3.3 V loss

If 3.3 V collapses:

- the PCM3168A digital/control domain becomes invalid;
- the external codec mute/reset path must assert;
- the final hardware wet/output mute must suppress rail-collapse transients;
- no design claim may rely on the TMUX1574 alone retaining a valid +3.3 V attenuation reference after the rail has disappeared.

The complete safety system therefore has three layers:

1. codec reset/mute;
2. SSI2164 safe-control selector while 3.3 V is valid;
3. final hardware wet/output suppression for reset and rail-collapse transients.


# Corrected local control buffers

The former unbuffered path placed approximately 3 kΩ in series with the SSI2164 nominal 10 kΩ control input and could only deliver approximately 2.54 V from a 3.3 V request. That implementation is rejected.

One OPA4196 quad buffer is shared across sheets 05 and 06 as `U63`:

```text
unit 1 = Memory VC1 buffer
unit 2 = Ghost VC2 buffer
unit 3 = Return VC3 buffer
unit 4 = wet-master VC4 buffer
unit 5 = protected +/-12 V common power
```

Each channel uses the existing high-impedance 1 kΩ / capacitor pre-buffer filter, a unity follower, a 20 Ω output-isolation resistor and post-buffer 0 V / +3.3 V clamps. The OPA4196 footprint remains blank pending exact footprint review.

At the lowest specified SSI2164 control-port impedance and nominal 3.3 V reference:

```text
VC = 3.3 V × 9 kΩ / (9 kΩ + 20 Ω)
   = 3.2927 V
attenuation ≈ 3.2927 / 0.033
            ≈ 99.8 dB
```

Using the current resistor-only lower 3.3 V rail estimate of 3.244 V gives approximately 98.1 dB attenuation. Regulator-reference tolerance remains part of the later rail acceptance calculation; the series-loading defect is closed.

The OPA4196 is powered from protected +/-12 V so 0 V remains a true mid-rail unity command. It is not part of the seven-package OPA1679 audio allocation.

# Release sequence

The selector remains on the safe +3.3 V inputs until all conditions are true:

```text
3.3 V supervisor valid
quiet 5 V codec rail valid
PCM3168A clocks valid
PCM3168A configuration readback valid
SAI DMA valid and zero-initialised
MCP4728 address valid
MCP4728 normal registers written and read back where possible
MCP4728 EEPROM safe-state checked during bring-up
Return control request = maximum attenuation
wet master request = maximum attenuation
watchdog active
no combined hardware fault
```

Then:

1. raise `SAFE_CONTROL_RELEASE`;
2. verify the selector changed to MCP4728 control;
3. ramp wet master from maximum attenuation;
4. ramp Memory/Ghost/Return channels from maximum attenuation as required.

Any failed condition returns `SAFE_CONTROL_RELEASE` low before software attempts recovery.

# Reset and watchdog timing

## TPS3808 supervisor

Selected configuration:

```text
TPS3808G33
50 kΩ from CT to VDD
approximately 300 ms reset delay
```

Purpose:

- hold reset/fault state through 3.3 V rise;
- provide enough time for regulator and clock stabilisation;
- keep the hardware selector on the attenuation reference during startup.

The exact worst-case delay must be recalculated from the selected resistor tolerance and datasheet limits in the native schematic.

## TPS3431 independent watchdog

Selected configuration target:

```text
CWD = 10 kΩ to VDD
SET1 = high
watchdog timeout approximately 200 ms nominal
published range approximately 170–230 ms
reset output pulse approximately 170–230 ms
```

The TPS3431 remains an independent MCU-hang detector and reset source.

## Critical timing distinction

V5.1 requires:

```text
emergency wet/Return suppression begins within 20 ms
```

The TPS3431 cannot detect an MCU hang within 20 ms. Its shortest practical watchdog windows remain longer than that, and the selected preset is approximately 200 ms.

Therefore the accepted interpretation is:

```text
20 ms = fault assertion to wet/Return suppression
not
20 ms = maximum MCU-hang detection time
```

Once any fault signal is asserted, the analogue selector and hardware mute path must begin suppression within 20 ms. The selector itself is much faster; board-level RC filtering, mute ramps and output switching must be designed so the complete assertion-to-suppression path remains within the 20 ms requirement.

The TPS3431 detects a stalled MCU later, then asserts that same fast clamp/reset path.

## Conditions requiring immediate clamp assertion

These do not wait for the watchdog timeout:

- MCU explicitly enters ERROR-MUTED;
- manual SAFE_MUTE;
- RESET_CLEAR sequence begins;
- 3.3 V supervisor fault;
- codec clock/configuration fault detected by hardware/firmware;
- codec rail validity fault;
- SAI/DMA error detected by running firmware;
- abnormal Return/limiter warning escalates to error.

## Condition requiring watchdog detection

```text
MCU stops executing and cannot assert its own fault output
```

This is detected in approximately 170–230 ms by TPS3431, after which suppression propagation must meet the 20 ms assertion-to-mute requirement.

If a later requirement demands detection of an MCU hang itself within 20 ms, TPS3431 must be replaced or augmented with a faster independent heartbeat detector. This lane does not claim otherwise.

# Bring-up tests

```text
[ ] Power with MCU absent: SSI controls remain at safe attenuation.
[ ] Power with MCP4728 absent: SSI controls remain at safe attenuation.
[ ] Power with MCP4728 EEPROM unprogrammed: selector blocks its outputs.
[ ] Hold MCU reset: selector remains on +3.3 V safe reference.
[ ] Assert supervisor fault: clamp begins within 20 ms.
[ ] Assert manual SAFE_MUTE: clamp begins within 20 ms.
[ ] Stop watchdog heartbeat: TPS3431 asserts within its documented window.
[ ] After watchdog assertion, clamp begins within 20 ms.
[ ] Short I2C bus: selector remains safe.
[ ] Request negative/overrange DAC control in firmware: hardware prevents SSI control below 0 V.
[ ] Release conditions out of sequence: clamp does not release.
```

# Risk closure

R3 — SSI2164 control polarity/range is closed for schematic preparation.

R4 — MCP4728 startup state is closed for schematic preparation, with the hardware selector as the authoritative safety layer.

R5 — watchdog timing architecture is conditionally closed:

- TPS3431 remains accepted as the slower independent hang/reset watchdog;
- the 20 ms requirement applies from asserted fault to suppression;
- TPS3431 package, land-pattern and assembly review remain open until the footprint gate.
