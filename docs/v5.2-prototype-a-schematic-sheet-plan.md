# V5.2 — Prototype A Schematic Sheet Plan

## Status

Draft schematic-capture plan.

## Purpose

Define a hierarchical schematic structure that preserves the accepted V5.1 signal flow, safety boundaries, SMD-first construction, and Thonkiconn requirements.

This document does not create PCB placement or routing authority.

## Schematic hierarchy

```text
00_TOP
├── 01_POWER_PROTECTION
├── 02_MCU_CLOCK_DEBUG
├── 03_CODEC_CONVERSION
├── 04_INPUT_PRESSURE_ABSENCE
├── 05_MEMORY_GHOST_WET
├── 06_RETURN_BREAK_LIMITER
├── 07_OUTPUT_MUTE_PROTECTION
├── 08_CONTROLS_STATE
└── 09_TEST_SERVICE
```

Each child sheet must have one clear responsibility.

Cross-sheet connections must use explicit hierarchical labels. Hidden global labels are limited to power rails, ground/reference nets, reset/fault nets, and the audio clocks.

### Output rails

### Safety/control outputs

```text
PWR_GOOD_N
WATCHDOG_FAULT_N
SYSTEM_FAULT_N
HW_ATTENUATE
CODEC_RESET_N
MCU_RESET_N
```

### Required design details

- reverse-polarity protection
- supply-entry filtering
- regulator enable states
- current-limit-compatible bench bring-up
- local bulk capacitance
- regulator compensation/magnetics
- supervisor delay network
- independent watchdog timing network
- open-drain fault combination or equivalent safe logic
- labelled test points for every rail

### ERC rules

- no power-output conflict between regulators
- all regulator grounds/reference pins explicitly connected
- no unpowered logic input through a higher-voltage domain
- fault outputs have defined pull state
- no floating enable/reset pins

### Clocking

- HSE crystal/oscillator circuit selected during schematic capture
- MCU audio PLL generates audio clocks
- 48 kHz audio rate
- preferred 24.576 MHz MCLK, subject to codec clock-table verification
- 12.288 MHz BCLK for eight 32-bit TDM slots
- 48 kHz LRCLK

### Memory documentation note

Add a schematic note:

```text
2.0 s × 48 kHz × 32-bit mono = 384,000-byte AXI SRAM history buffer.
No external audio RAM on Prototype A.
```

### Required support

- all VDD/VSS pins shown or correctly represented in multi-unit symbol
- decoupling at every supply pin group
- VCAP capacitors per official MCU requirements
- VDDA/VREF handling explicit
- BOOT configuration explicit
- NRST supervisor/manual path explicit
- SWD connector/header
- watchdog heartbeat test point
- spare debug UART pads allowed as service-only, not panel I/O

### ERC rules

- no hidden unpowered MCU supply pins
- all boot/config pins have defined states
- unused GPIOs handled deliberately
- no 5 V signal reaches a non-tolerant MCU pin

### Required analogue sub-blocks

- reset/mute defaults are safe

## 06_RETURN_BREAK_LIMITER

### Purpose

Implement the only legal path from Return DAC output back to Memory and Absence.

### Major parts

- SSI2164 channel 3
- MCP4728 channel C
- OPA1679 stages
- Break/nonlinear/limiter devices selected during schematic capture

### Mandatory path

```text
RETURN_DAC_RAW
  ↓
RETURN_LEVELLED
  ↓
BREAK_OUT
  ↓
RETURN_NONLINEAR
  ↓
RETURN_LIMITED
  ├── RETURN_FEED_TO_SUM
  └── ABSENCE_INFLUENCE
```

### Forbidden nets

The following direct paths are forbidden:

```text
RETURN_DAC_RAW → MEMORY_SUM
BREAK_OUT → MEMORY_SUM
RETURN_NONLINEAR → MEMORY_SUM
```

Only `RETURN_LIMITED` may leave the safety boundary.

### Mandatory test points

```text
TP_RETSEND
TP_BREAK
TP_RETURN_NONLINEAR
TP_RETLIM
TP_RETURN_CTRL
TP_ABSCTRL
```

### Safety notes

The schematic must contain a visible note:

```text
Normal maximum small-signal loop target ≈ 0.85.
Complete Return loop must remain bounded.
```

The limiter must remain effective during MCU/codec faults.

### ERC rules

- `HW_ATTENUATE` reaches Return VCA/clamp
- Return level control has a defined power-up state
- limiter rails/references remain powered when digital core faults
- `RETURN_LIMITED` is the only exported feedback-audio net

## Symbol and footprint gates

Before a symbol is accepted:

- pin numbers checked against official datasheet
- all power/ground pins accounted for
- exposed pad behavior documented
- active-low names use `_N`
- multi-unit parts have explicit power unit where needed

Before a footprint is associated:

- package drawing checked against official manufacturer drawing
- pin-1 orientation checked
- thermal/exposed pad checked
- courtyard and assembly clearances reviewed
- hand/reflow assembly method stated

For WQP518MA:

- exact switched-contact pins verified
- footprint dimensions checked against the current manufacturer drawing
- panel axis and nut clearance recorded

## ERC acceptance rules

ERC must pass with no unexplained:

- unconnected required pins
- power-input-without-source warnings
- output-to-output conflicts
- floating analogue inputs
- unpowered logic/control pins
- unnamed feedback paths
- active-low reset nets without defined pull state

Intentional exceptions must be recorded in a schematic review note, not silently excluded.

## Schematic review order

Review in this sequence:

1. power and reset
2. MCU/clock/debug
3. codec supplies and clocks
4. input and direct Present path
5. converter boundaries
6. Memory/Ghost wet path
7. Return/Break/limiter path
8. output mute/protection
9. controls and LEDs
10. test/service access
11. whole-system ERC
12. independent Return-safety review

## Stop rule

Schematic capture is not accepted until:

```text
[ ] all sheets exist
[ ] every hierarchical port is connected once in the intended direction
[ ] direct Present works without the digital core
[ ] only RETURN_LIMITED feeds Memory/Absence
[ ] hardware attenuation is independent of firmware
[ ] codec clock mode is verified
[ ] power-up/reset sequence is explicit
[ ] all exact packages/footprints are verified
[ ] ERC passes with documented exceptions only
```

PCB placement and routing remain forbidden until this review is complete.
