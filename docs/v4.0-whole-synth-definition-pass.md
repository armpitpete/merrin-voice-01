# V4.0 — Whole Synth Definition Pass

## Purpose

This document starts the actual V4.0 definition pass for Merrin Grief Synth.

It answers the current working question:

```text
What is the complete Merrin Grief Synth beyond the current browser voice?
```

This is still documentation/specification work only.

Do not add code, demo media, plugin work, VCV work, sequencer work, M A C controller work, DBHT-1 expansion work, or hardware expansion in this pass.

## Current accepted foundation

The accepted foundation remains:

```text
Merrin Voice 01 — Merrin Grief Synth: Constrained Grief
```

It currently proves:

- one emotional voice
- constrained pitch identity
- playable browser Web Audio implementation
- on-screen keyboard input
- computer keyboard input
- MIDI keyboard input
- active note display
- MIDI diagnostics and panic behaviour
- Shape: Pure / Hollow / Pressed
- Sub as weight, not bass boom
- Overtone as ache, not brightness
- Drift as slight instability
- Tone / Fade / Echo / Amplitude
- Scale / Glide / Weight / Wither
- live oscilloscope accepted as functional

## Whole synth answer — draft v0.1

The complete Merrin Grief Synth should be:

```text
A finished, focused, browser-first emotional instrument built around Constrained Grief, with a clean performance surface, hidden diagnostics, stable input behaviour, and a final accepted control language.
```

It is not:

```text
a general synth, workstation, sequencer, VST, VCV module, hardware product, DBHT-1, or M A C controller.
```

## What complete means

The whole synth is complete when these parts are true:

1. The voice identity is stable.
2. The main performance surface is clear.
3. Diagnostics are available but no longer dominate the instrument.
4. The final control set is accepted.
5. The signal path language is final enough to explain.
6. MIDI/input behaviour is stable and recoverable.
7. Panic/reset/release behaviour is safe.
8. The app can be used by someone arriving cold.
9. The repo clearly says what the synth is and is not.
10. Final demo media can then be recorded honestly.

## Final instrument shape

The whole synth should remain browser-first.

The complete instrument should have two visible layers:

```text
Performance layer
Advanced/test layer
```

### Performance layer

The performance layer is the instrument.

It should contain:

- title / short identity sentence
- start audio / status / panic
- main playable controls
- voice-shaping controls
- emotion-shaped controls
- note input surface
- simple state feedback
- active-note visibility
- optional basic oscilloscope if it supports play rather than debugging

### Advanced/test layer

The advanced/test layer is for development, setup, and hardware trouble.

It may contain:

- MIDI diagnostics
- raw MIDI monitor
- effect test switches
- All effects off
- Normal voice reset
- Wither delay
- detailed voice state
- technical warnings

These must not feel like the public instrument surface.

## Final signal path

The final conceptual signal path should remain:

```text
Scale
  ↓
Tone
  ↓
Envelope
  ↓
Room
  ↓
Memory
```

Module-language form:

```text
MV-02 Scale
  ↓
MV-01 Tone
  ↓
MV-03 Envelope
  ↓
MF-01 Room
  ↓
MF-02 Memory
```

Plain-language form:

```text
where the note is allowed to go
  ↓
what kind of voice speaks
  ↓
how it arrives and leaves
  ↓
what space holds it
  ↓
what trace remains
```

## Whole-synth behaviours to verify

### 1. Constrained grief remains audible

Changing controls should not turn the synth into a normal bright general-purpose synth.

### 2. Fast play does not break the identity

Fast note input may work, but it should not redefine the synth as a lead/pluck instrument.

### 3. Same-note retrigger remains stable

Repeated notes should retrigger musically and not overload.

### 4. MIDI input remains stable

MIDI note-on/note-off should work without stuck notes, duplicate spam, or unsafe volume jumps.

### 5. Scale change remains safe

Changing scale must not leave illegal/stuck notes hanging.

### 6. Panic works

Panic must reliably silence active notes and recover normal play.

### 7. Diagnostics do not dominate

A cold visitor should see an instrument first, not a test rig.

### 8. The voice can return to accepted state

The player should be able to return from experiments to the accepted voice.
